## 2. 硬约束（违反即失败，不要"顺手改进"）

- **协议与行为逐字节兼容。** 这是最高优先级约束。以下两个文件**冻结**，
  两仓库 SHA256 必须一致，**永远不要修改**：
  - `src/core/net/protocol.h` → `98627727e1fbda3a…`
  - `tests/test_protocol.cpp` → `d779bb06d41b7312…`
  - **绝不要**给 `protocol.h` 加 `Q_DECLARE_METATYPE`
- 协议事实（不要重新发明）：`TCP 8887` 信令，UTF-8 文本行 `'\n'` 结尾；
  `UDP 12345` 双向裸 PCM S16_LE/16000Hz/单声道，每包 320 帧（640 字节），**无包头**；
  `UDP 23456` 单向视频 PC←T113，每个数据报一整个 JPEG，`save(&buffer,"JPEG",75)`；
  `UDP 50000` 预览裸文本 `"getframe"`/`"stop"`（**不带 `\n`**），50ms 定时器 = 20fps。
- **C++11**：禁用 inline 变量、结构化绑定、`if constexpr`、`std::optional`、
  `std::string_view`、`std::make_unique`、`std::filesystem`。
  `constexpr auto`、`std::shared_ptr`、`std::atomic` 可用。
- **Qt5 是目标，不要迁移 Qt6。** API 下限 Qt 5.9：禁用 `errorOccurred`、
  `QStringView`、`QColorSpace`、`QRandomGenerator`、`QMetaObject::invokeMethod(obj, functor, type)`。
  用 `QTimer::singleShot(msec, context, functor)`（Qt 5.4+）替代。
- **不改 UI 布局、不改端口/信号字符串、不升 Qt 版本。**
- **新功能一律"默认关闭"**，保证未配置时行为逐字节不变

## 6. 工作方法（这套方法本身已经被验证过，请沿用）

### 6.1 每个新规则 / 新测试都要配故障注入夹具

夹具是**就地改写真实源码**、编译、跑、再还原。核心铁律：

1. **所有就地改写夹具共用同一把锁名 `fi37_rewrite.lock`**，防止并发互踩。
   锁被占用 → 退出码 **3**（`2` 表示夹具自身错误）。
2. **绝不 kill 正在改写源码的夹具**；**绝不**在扫描期间跑 `verify.py` / `ctest`。
3. **还原是 4 层防御**（`atexit` + 信号钩子 + `finally` + 启动时检测）。
   宁可留下污染，也不要静默删掉合法的改动。
4. **锚点与期望值会静默过期**（第 76 条）。锚点唯一性要自证。
5. **永不执行的错误分支是 bug 温床**（第 7 条）—— 要么让它可达，要么删掉。
6. **要证明规则的适用范围有判别力**（第 8 条）。
7. **检查器本身也要被检查**（第 9 条）：`verify.py` 会从 `main()` 源码里数
   已注册的 `check_*`，有孤儿就报 `[harness-crash]`。
   **任何守卫/检查代码都要先证明它真的会变红。**
8. **静态规则证明"形态"，单元测试证明"语义"**（第 79 条）。
   这个分工要写进规则注释里，**并且要证明这个分工成立**（运行期变异）。
9. **变异必须模拟真实退化**：
   - 把"没接线"写成 `if (false)` 是在测检查器的实现细节 —— 真实退化是整段代码不存在。
   - "只删声明"会让 `.cpp` 编不过 —— 那是语法错误，不是退化。
   - 只改 N 处同名资源中的 1 处，不构成"不一致"。
10. **同一个资源名散落多处就一定会不一致**（第 80 条）：要么收敛单点真相，
    要么给出**明确优先级 + 可查的失败**。
11. **清理注释不是纯文档操作**（第 81 条）：夹具锚点可能嵌在注释里。
    批量清理前先枚举、分类、**逐条复核保留项** —— 第一批噪声里就混着 2 行真说明。

### 6.2 需要警惕的"假绿"类型（都真实发生过）

- **判据搜到了签名里的词**：规则只搜 `configured`，而它本来就在
  `const QString& configured` 里 —— 删掉整段逻辑仍然通过。判据要看**动作**。
- **搜索 token 出现在别处**：只查 `t113_test_resource_paths`，而它也出现在
  `add_executable` 里 —— 删掉 `add_test` 仍然通过。
- **文件级判据 VS 函数级判据**：文件里已有一个带闸门的提交点，
  再加一个不带闸门的也会判绿。必须按**提交点所在函数**判定。
- **别人的失败冒充自己的成功**：夹具把"基线本来就红的 FAIL 行"当成"变异被抓到"。
- **`errors="replace"` 掩盖编码错误**，让"读不出来"伪装成"内容不对"。
- **件声明"实测结论"也可能是错的**（第 66 条）：注释里写"探 127.0.0.1 在两个
  平台都会失败"，实测是错的，导致 7 个用例长期失败。**凡"我实测过"的断言，
  都值得再实测一次。**

1. 写代码 + 写/更新测试 + 写/更新夹具（**三件一起**，不要事后补）
