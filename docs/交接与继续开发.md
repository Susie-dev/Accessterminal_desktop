一、必须遵守的硬约束（改任何代码前先读这一节）
--------------------------------------------------------------------------------

这几条是重构的前提，**破坏它们等于把整个重构做废**：

1. **TCP 8887 信令语义逐字节兼容（与门口机配对）**
   - 室内机是**服务端**（`SignalingServer`），门口机是发起方
   - 门口机 -> 室内机：`call`、`stopsend`、`unlock`
   - 室内机 -> 门口机：`accept`、`recstop`、`unlock`
   - 一律 UTF-8 文本行 + `'\n'` 结尾
   - **收 `recstop` 时不要回发 `stopsend`**（只有本地挂断才发）

2. **UDP 报文格式与端口不可改（与门口机配对）**
   - `12345` 双向音频：裸 PCM，S16_LE / 16000 Hz / 单声道 /
     每包 320 帧（640 字节），**无包头**
   - `23456` 视频（室内机**收**）：每包一个**完整 JPEG**，不做重组/重传
   - `50000` 远程监看：室内机发裸 `"getframe"` / `"stop"`
     （**没有 `'\n'`**），门口机收到后才推流
   - 音频那边写 "JPG"、视频那边写 "JPEG" —— 这个不对称是 baseline 的，
     **照抄，别"顺手统一"**

3. **生命周期约定**
   - 门口机侧的音视频线程只在收到 `accept` 之后创建（室内机发出 `accept`
     的时机因此是有语义的，不要提前/推后）
   - 异步任务不得在对象析构后访问它（README 约定第 3 条）
   - `~Widget()` **必须发 `"stop"`** 关掉远程监看 ——
     实测 baseline 的 `~Widget() { delete ui; }` **从不发 `"stop"`**，
     导致门口机的推流线程一直空转。**不要改回去**。
     - **勘误（本轮修正）**：本文档此前写着「重构版已修正这一点」，这句话
       **是错的**。重构版同样没有发 `"stop"`：`Widget` 析构只做
       `destroyCallForm(); delete ui;`，而 `MonitorClient::stop()` 当时只
       关闭本地 socket 并发 `activeChanged(false)`，**从不向门口机发送任何
       报文**。`git show` 逐个确认过 `368c98b`、`305eda8`（补测试那次）与
       重构基线 `7ce1641`，`stop()` 的实现三处完全一致，从未修过。
     - 危害是真实的：门口机 `CameraUdpServer` 只在收到 `Stop` 时才
       `sendTimer->stop()`，本地关 socket 对它**不可观测**，它会继续按
       50ms（20fps）朝一个已消失的地址推 JPEG。用户「监看中途直接关掉
       程序」是最常见的操作，正好走这条路。
     - **真正的修复位置在 `MonitorClient::stop()`**（不是 `~Widget()`）：
       关闭 socket **之前**，若 `m_active && m_socket` 则
       `writeDatagram(kStop, ...)`。放在这里是因为"退出接收态"这个动作
       有两个入口 —— 显式 `stop()` 和析构 —— 而 `~Widget()` 两者都不直接
       调用，它靠 Qt 的子对象机制 → `~MonitorClient()` → `stop()`。
       在 `stop()` 里发是**唯一**能同时覆盖"主动停止"与"关程序退出"的位置。
     - 由两条行为用例钉住（`test_monitor_client.cpp` 的
       `stopWhenActiveNotifiesTerminal`、`destructorOfActiveClientNotifiesTerminal`）
       **加上** `tools/verify.py` 的 `check_monitor_client_contract_is_pinned`
       静态规则（限定在 `stop()` 函数体内，否则会被 `toggle()` 里的同名调用
       顶包）。三条都做过故障注入验证。

4. **不迁移 Qt 版本**：目标就是 Qt5。

5. **C++11**，不是 C++14/17。禁用：`inline` 变量、结构化绑定、`if constexpr`、
   `std::optional`、`std::string_view`、`std::make_unique`、`std::filesystem`。

6. **`src/core/net/protocol.h` 与 `tests/test_protocol.cpp` 是冻结文件**，
   必须与门口机仓库**内容完全一致**：
       protocol.h         SHA256 = 98627727e1fbda3a54dcb27d84a6a49e33b775990508f4ea89d167d518005523
       test_protocol.cpp  SHA256 = d779bb06d41b73126d37ea6f0bd97f910f6201696c25c3befeea078ccce6d52d
   **绝对不要往 protocol.h 里加 `Q_DECLARE_METATYPE`**（会破坏冻结约定）。
   改这两个文件前先读 `tools/check_protocol_sync.py`，改完**两个仓库都要同步**。

7. **不要做全仓库 CRLF -> LF 的批量转换**。只规范化你实际改过的文件。
   所有新文件必须 **LF、无 BOM**。

### 故障注入自检（本工程最有价值的东西）

`tools/verify_*.py` 里有 **22 个夹具**，每一个都会把**被测代码**故意改坏，
重新编译、重新跑测试，然后断言"测试**必须**变红"。
如果一个变异没被抓到，说明**那个测试没有判别力**，等于没测。

**每写一条新的静态规则、每写一个新的测试，都必须配一个这样的夹具。**

**跑这些夹具时的铁律**：
  1. **一次只跑一个**。两个会改写源文件的夹具并行会互相污染。
  2. **不要在夹具扫描期间跑 `verify.py`**（会读到中间状态，报假告警）。
  3. **绝不要 `kill` 一个正在改写源文件的夹具**（虽然它们有还原保险）。

### 【P2】"退格双删"类缺陷的全面排查（与门口机同源）

门口机在 `form_passwd.cpp` 上发现：`uic` 生成的 `setupUi()` 会调
`connectSlotsByName(this)`，把 `on_btnbck_clicked` 之类按命名约定自动接上；
若 .cpp 又**显式 `connect` 一次**，槽就被连两遍（信号发一次、槽执行两次）。

**现状（第 36 轮据实核对）**：

  - 两个 `.ui`（`widget.ui` / `form_phonecall.ui`）里都**没有** `<connections>`
    块，因此不存在"uic 自动接线 + 显式 connect"叠加出来的双连。
  - `widget.ui` 的 8 个按钮 objectName 与 `widget.h` 里 8 个 `on_*_clicked`
    槽**一一对应**（`diff` 无差异），而且这 8 个槽现在**全部被
    `desktop_test_widget` 用真实 `click()` 驱动**：若某个槽被连了两遍，
    灯控用例里的 `QCOMPARE(fakeSerialPort().writes.size(), 1)` 会立刻变红。
    这也是【P1】里坚持"点真实按钮、不要直接调私有槽"的原因 —— 后者会绕开
    `connectSlotsByName`，把这类缺陷一起绕过去。
  - `form_phonecall.cpp` 里没有任何对 `on_*` 槽的显式 connect，但它自己的
    交互（滑块接听、挂断按钮）还没有行为测试 —— 随【P1】第 2 项一起做。

**方法**（对新加的窗体沿用）：

  - 找出所有形如 `on_<对象名>_<信号名>` 的槽
  - 检查 `.ui` 里有没有 `<connections>` 块（有则 uic 会自动接线）
  - 检查 .cpp 里有没有对这些槽的显式 `connect`
  - 两者同时成立 => 双连，需要行为测试钉住或修复

六、什么样的改动才算"做完了"
--------------------------------------------------------------------------------

沿用本项目已经形成的标准：

  1. **断言必须落在"输出"上**：线上字节、串口写入、发出的信号、
     走了哪个日志分支。—— "有测试"不等于"被测到"。
  2. **新测试必须配故障注入**，并证明"把被测代码改坏它就会红"。
     在缺陷代码上不失败的测试**没有价值**。
  3. **行为不可观测的防御性代码，也要有静态规则守**，并在夹具里如实
     记入 `UNDETECTABLE` **并写明原因**。
  4. **报覆盖率必须连分母一起报**，并把未覆盖行分成"不可达 / 可达未测"。
  5. **"X 不出现"的断言必须配阳性对照**。
  6. **优先链接真实实现**，别复制一份进替身（除非确实链接不进来，
     且要在注释里说明那是副本、由哪条静态规则守）。
